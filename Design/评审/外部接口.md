## 一、文档概述

### 1.1 背景与目标

本项目基于 Dify 搭建统一知识库门户，覆盖 **9 个业务知识库**：基金、合规、信评、量化、运营、固收投研、股票、风控、前台运维。

整体架构采用 **Dify 做编排 + 自研做核心** 的混合模式。本接口文档定义自研核心服务对外暴露的全部 RESTful API，供 Dify 编排层、前端 UI 及外部系统调用。

### 1.2 接口全景

| 模块 | 接口数量 | 核心功能 |
| :--- | :--- | :--- |
| **文档预处理**（任务2/3） | 5 | 文档上传、状态查询、列表查询、详情查询、手动重试 |
| **全局路由**（任务4） | 3 | 路由查询、配置热加载、健康检查 |
| **意图理解与改写**（任务5） | 2 | 查询处理、健康检查 |
| **混合检索**（任务6） | 1 | 多路召回（含Rerank可插拔） |
| **排序加权**（任务7） | 1 | 综合重排序 |
| **多步规划**（任务9） | 4 | ReAct模式、流式响应、反问恢复 |
| **文档版本管理**（任务8） | 6 | 版本变更、审批确认、重新索引 |
| **召回评测**（任务10） | 8 | 黄金集管理、评测触发、报告获取 |
| **反馈闭环**（任务11） | 9 | 反馈采集、根因分析、优化审批 |

> **说明**：任务8（文档版本管理与整体联调）的接口在本文档中统一收录于“文档管理”模块，涵盖版本管理与联调运维功能。


## 二、通用规范

### 2.1 基础信息

| 项目 | 规范 |
| :--- | :--- |
| **Base URL** | `https://{your-domain}/api/v1` |
| **协议** | HTTPS |
| **字符编码** | UTF-8 |
| **数据格式** | JSON（文件上传接口使用 `multipart/form-data`） |
| **时间格式** | ISO 8601（如 `2026-08-10T14:32:18Z`） |
| **分页规范** | `page`（从1开始）+ `limit`（默认20，最大100） |

### 2.2 认证方式

所有 API 请求均需在 HTTP Header 中携带 API Key 进行认证：

```http
Authorization: Bearer {DIFY_API_KEY}
```

**关键说明**：
- API Key 与 Dify 平台的知识库 API Key 对齐，具有访问该账户下所有可见知识库的权限
- API Key 必须存储在服务端，严禁嵌入客户端代码或公开暴露
- 缺失或无效的 API Key 将返回 `401 Unauthorized`

### 2.3 统一响应结构

**成功响应**：

```json
{
  "code": 0,
  "data": { ... },
  "message": "success",
  "trace_id": "trace_abc123"
}
```

| 字段 | 类型 | 描述 |
| :--- | :--- | :--- |
| `code` | integer | 业务状态码，`0` 表示成功 |
| `data` | object | 业务数据 |
| `message` | string | 可读的描述信息 |
| `trace_id` | string | 全链路追踪ID，贯穿所有日志表 |

**错误响应**：

```json
{
  "code": "error_code",
  "message": "可读的错误描述",
  "status": 400,
  "details": { ... }
}
```

### 2.4 统一错误码体系

| Code | HTTP Status | 类别 | 描述 | 建议客户端行为 |
| :--- | :--- | :--- | :--- | :--- |
| `40001` | `400` | 请求错误 | 文件为空或未上传 | 提示用户重新上传 |
| `40002` | `400` | 请求错误 | 不支持的文件扩展名 | 提示允许的格式列表 |
| `40003` | `413` | 请求错误 | 文件超过大小限制（50MB） | 提示文件过大 |
| `40004` | `404` | 资源不存在 | `source_kb` 在 Dify 中不存在 | 检查知识库ID是否正确 |
| `40005` | `401` | 认证失败 | API Key 无效或过期 | 重新获取有效 Key |
| `40006` | `400` | 请求错误 | `doc_uuid` 格式非法 | 检查 UUID 格式 |
| `40301` | `403` | 权限不足 | 超过最大重试次数 | 联系管理员或使用 `force=true` |
| `40302` | `403` | 权限不足 | 无重试权限 | 仅管理员可重试 |
| `40401` | `404` | 资源不存在 | 文档不存在 | 检查 `doc_uuid` 是否正确 |
| `40901` | `409` | 资源冲突 | 文档正在处理中 | 等待处理完成后再重试 |
| `50001` | `500` | 服务内部 | MinerU 服务不可用 | 自动重试（指数退避） |
| `50002` | `500` | 服务内部 | MinerU 解析超时（120s） | 同上 |
| `50003` | `500` | 服务内部 | MySQL 写入失败 | 重试，持续失败则发告警 |
| `50004` | `500` | 服务内部 | ES/Milvus 写入失败 | 重试，补偿任务处理 |
| `50005` | `500` | 服务内部 | 对象存储（MinIO）写入失败 | 重试 |
| `invalid_param` | `400` | 请求错误 | 请求参数缺失或格式错误 | 检查请求体 |
| `unsupported_role` | `400` | 请求错误 | 用户角色未在配置表中定义 | 检查角色配置 |
| `feedback_not_found` | `404` | 资源不存在 | 反馈记录不存在 | 检查 ID |
| `analysis_in_progress` | `409` | 资源冲突 | 分析任务正在进行中 | 等待完成 |
| `run_not_found` | `404` | 资源不存在 | 指定的评测运行不存在 | 检查 run_id |
| `run_not_completed` | `400` | 请求错误 | 评测运行尚未完成 | 等待完成后再设置基线 |
| `dataset_version_conflict` | `409` | 资源冲突 | 黄金问答集版本冲突 | 检查版本号 |


## 三、文档预处理接口（任务2/3）

### 3.1 触发文档预处理

**路径**：`POST /documents/ingest`

**功能**：接收文件流和元数据，触发异步处理管道。支持**同步（阻塞）** 和**异步（立即返回 task_id）** 两种模式。

**请求体**（`multipart/form-data`）：

| 字段名 | 类型 | 必填 | 校验规则 | 描述 |
| :--- | :--- | :--- | :--- | :--- |
| `file` | `binary` | ✅ | 大小 ≤ 50MB；扩展名白名单：`.pdf,.docx,.doc,.xlsx,.pptx,.txt,.md` | 原始文件流 |
| `source_kb` | `string` | ✅ | 长度 ≤ 32；必须在 Dify 中存在 | 知识库标识 |
| `doc_type` | `string` | ❌ | 枚举：`report` / `announcement` / `contract` / `research` / `other` | 文档分类 |
| `published_date` | `string` | ❌ | ISO 8601 日期（如 `2026-07-01`） | 文档发布日期 |
| `tags` | `string` | ❌ | 逗号分隔，每个 Tag ≤ 20字符，最多10个 | 例如 `"新能源,城投债,AAA评级"` |
| `async_mode` | `boolean` | ❌ | 默认 `false` | `true` 异步；`false` 同步等待（最长120s） |

**成功响应（异步模式，`async_mode=true`）**：

HTTP Status: `202 Accepted`

```json
{
  "code": 0,
  "data": {
    "doc_uuid": "doc_20260810_a1b2c3d4",
    "task_id": "task_20260810_x9y8z7w6",
    "status": "pending",
    "check_status_url": "/api/v1/documents/status/doc_20260810_a1b2c3d4"
  },
  "message": "Document accepted for processing",
  "trace_id": "trace_abc123"
}
```

**成功响应（同步模式，`async_mode=false`）**：

HTTP Status: `200 OK`（处理完成）或 `202 Accepted`（超时转异步）

```json
{
  "code": 0,
  "data": {
    "doc_uuid": "doc_20260810_a1b2c3d4",
    "version": "v1.0",
    "action": "new",          // new | skip | retry
    "status": "indexed",      // indexed | failed | processing
    "chunk_count": 156,
    "elapsed_time_sec": 45.3,
    "indexed_at": "2026-08-10T14:33:03Z"
  },
  "message": "Document indexed successfully",
  "trace_id": "trace_abc123"
}
```

**Hash命中跳过响应**：

HTTP Status: `200 OK`

```json
{
  "code": 0,
  "data": {
    "doc_uuid": "doc_existing_123",
    "action": "skip",
    "message": "Duplicate document (same file_hash), skipping"
  },
  "trace_id": "trace_abc123"
}
```

| `fields` | Query | ❌ | `basic`（默认）/ `detailed`（含节点级耗时） |

**请求体**：

| 字段 | 类型 | 必填 | 描述 |

## 四、全局路由接口（任务4）

### 4.1 路由查询

**路径**：`POST /route`

**功能**：根据用户问题，通过**静态关键词匹配 + MCP 动态元数据增强**，自动路由到最相关的知识库【task4对外接口】。

**请求体**：

| 字段名 | 类型 | 必填 | 描述 |
| :--- | :--- | :--- | :--- |
| `user_query` | `string` | 是 | 用户原始问题，最大500字符 |
| `context_kb` | `string` | 否 | 用户当前所在知识库，用于上下文偏置 |
| `enable_mcp` | `boolean` | 否 | 是否启用 MCP 动态增强，默认 `true` |

**成功响应（精准命中）**：

HTTP Status: `200 OK`

```json
{
  "status": "success",
  "routed_kbs": ["固收投研"],
  "confidence": 0.85,
  "clarity_flag": "clear",
  "suggested_question": null,
  "filter_tags": ["城投债", "利差"],
  "matched_keywords": ["城投债", "利差"],
  "mcp_enhanced": false,
  "mcp_hint": null
}
```

**成功响应（MCP动态干预）**：

```json
{
  "status": "success",
  "routed_kbs": ["风控知识库"],
  "confidence": 0.92,
  "clarity_flag": "clear",
  "suggested_question": null,
  "filter_tags": ["城投债", "高风险主体"],
  "matched_keywords": ["城投债", "XX集团"],
  "mcp_enhanced": true,
  "mcp_hint": "当前债券主体触发风险预警，已优先为您匹配风控知识库。"
}
```

**成功响应（歧义命中）**：

```json
{
  "status": "success",
  "routed_kbs": ["固收投研", "信评知识库"],
  "confidence": 0.62,
  "clarity_flag": "ambiguous",
  "suggested_question": "您的问题涉及多个知识库，请选择：\n1. 固收投研（含MCP风险提示）\n2. 信评知识库",
  "filter_tags": ["债券", "信用风险"],
  "matched_keywords": ["债券", "风险"],
  "mcp_enhanced": true,
  "mcp_hint": "检测到该债券近期评级下调，建议优先关注信评知识库。"
}
```

**响应字段说明**：

| 字段名 | 类型 | 描述 |
| :--- | :--- | :--- |
| `status` | `string` | 固定返回 `"success"` |
| `routed_kbs` | `array[string]` | 推荐的知识库列表，最多3个 |
| `confidence` | `float` | 最高分知识库的置信度，范围0~1 |
| `clarity_flag` | `string` | `clear` / `ambiguous` / `unknown` |
| `suggested_question` | `string` | 歧义或零命中时的引导话术 |
| `filter_tags` | `array[string]` | 提取的业务标签，最多10个 |
| `matched_keywords` | `array[string]` | 命中的原始关键词，最多10个 |
| `mcp_enhanced` | `boolean` | 是否受到 MCP 动态信号干预 |
| `mcp_hint` | `string` | MCP 干预的原因说明 |

## 五、意图理解与改写接口（任务5）

### 5.1 查询处理

**路径**：`POST /query/process`

**功能**：对用户原始查询进行**意图识别、问题拆解与查询改写**，为混合检索提供标准化 Query 列表【task5对外接口】。

**请求体**：

| 字段 | 类型 | 必填 | 描述 |
| :--- | :--- | :--- | :--- |
| `query` | `string` | 是 | 用户原始查询文本 |
| `session_id` | `string` | 否 | 会话ID，用于多轮指代消解 |
| `source_kb` | `string` | 否 | 路由模块输出的知识库标识 |
| `user_id` | `string` | 否 | 用户标识，用于日志记录 |
| `trace_id` | `string` | 否 | 全链路追踪ID |

**请求示例**：

```json
{
  "query": "那个AAA城投的信用风险怎么样，现在能配吗？",
```

## 八、多步规划接口（任务9）

### 8.1 发起多步规划

**路径**：`POST /agent/run`

**功能**：启动一个多步规划任务，支持**流式（SSE）** 与**阻塞**两种响应模式【task9对外接口】。

**请求体**：

| 字段 | 类型 | 必填 | 描述 |
| :--- | :--- | :--- | :--- |
| `query` | `string` | 是 | 用户原始问题 |
| `inputs` | `object` | 否 | 应用输入变量（如用户角色） |
| `user` | `string` | 是 | 终端用户标识 |
| `conversation_id` | `string` | 否 | 会话ID，不传则新建 |
| `response_mode` | `string` | 否 | `streaming`（默认）或 `blocking` |
| `max_iterations` | `integer` | 否 | 最大规划循环轮次，默认3，上限5 |
| `retrieval_top_k` | `integer` | 否 | 每轮召回候选数量，默认10 |
| `confidence_threshold` | `float` | 否 | 置信度阈值，达到即停止检索，默认0.85 |
| `agent_config` | `object` | 否 | Agent级别配置覆盖 |

**请求示例**（流式）：

```json
{
  "query": "请对比分析2024年Q3和Q4的基金业绩，并说明原因。",
  "inputs": { "user_role": "基金经理" },
  "user": "user-123",
  "conversation_id": "conv-abc",
  "response_mode": "streaming",
  "max_iterations": 4,
  "confidence_threshold": 0.80
}
```

**流式响应事件**（`text/event-stream`）：

| 事件名称 | 触发时机 | 数据字段 |
| :--- | :--- | :--- |
| `agent_start` | 规划开始 | `task_id`, `conversation_id`, `iteration_count` |
| `agent_thought` | 每轮推理步骤 | `round`, `thought`, `tool_calls` |
| `agent_tool_result` | 工具调用完成 | `tool_name`, `result_summary`, `confidence` |
| `agent_evaluation` | 评估节点完成 | `overall_confidence`, `missing_info`, `contradictions`, `decision` |
| `agent_ask` | 需要反问用户 | `question`, `options`, `form_token` |
| `agent_answer` | 最终答案（增量） | `text`, `is_final` |
| `agent_end` | 规划结束 | `final_answer`, `total_rounds`, `usage` |
| `error` | 发生错误 | `status`, `code`, `message` |

**`agent_evaluation` 事件示例**：

```json
{
  "event": "agent_evaluation",
  "data": {
    "round": 2,
    "overall_confidence": 0.62,
    "dimensions": {
      "relevance": 0.70,
      "coverage": 0.55,
      "authority": 0.80,
      "consistency": 0.45
    },
    "missing_info": ["2024年Q4具体收益数据"],
    "contradictions": [
      {
        "field": "收益率",
        "value_a": "5.2%（来源：A基金季报）",
        "value_b": "4.8%（来源：B基金季报）"
      }
    ],
    "decision": "ask"
  }
}
```

## 十一、反馈闭环接口（任务11）

### 11.1 接收反馈

**路径**：`POST /feedback`

**功能**：接收来自 Dify 或其他渠道的反馈数据，写入 `kb_user_feedback` 表并触发异步根因分析【task11对外接口】。

**请求体**：

| 字段名 | 类型 | 必填 | 描述 |
| :--- | :--- | :--- | :--- |
| `trace_id` | `string` | 是 | 全链路追踪ID |
| `session_id` | `string` | 否 | 会话ID |
| `message_id` | `string` | 否 | Dify消息ID |
| `rating` | `string` | 是 | `thumbs_up` / `thumbs_down` |
| `comment` | `string` | 否 | 用户备注 |
| `source` | `string` | 否 | `dify_web` / `dify_api` / `custom` |
| `user_id` | `string` | 否 | 用户标识 |
| `metadata` | `object` | 否 | 扩展元数据 |

**请求示例**：

```json
{
  "trace_id": "trace_20260810_001",
  "session_id": "sess_001",
  "rating": "thumbs_down",
  "comment": "回答不相关",
  "source": "dify_web",
  "user_id": "zhangsan"
}
```

**成功响应**：

```json
{
  "code": 0,
  "data": {
    "feedback_id": 12345,
    "status": "pending"
  }
}
```
