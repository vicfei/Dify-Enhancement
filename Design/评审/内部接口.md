## 一、文档概述

### 1.1 背景与目标

本项目基于 Dify 搭建统一知识库门户，覆盖 **9 个业务知识库**，整体架构采用 **Dify 做编排 + 自研做核心** 的混合模式。

本接口文档定义**自研服务内部各模块之间的编程契约（Python ABC / Protocol）**，用于指导开发团队进行模块化并行开发、单元测试与集成联调。

### 1.2 与外部接口的关系

| 维度 | 对外接口（External API） | 对内接口（Internal SPI） |
| :--- | :--- | :--- |
| **目标受众** | Dify编排层、前端、外部系统 | 项目组后端开发人员 |
| **设计哲学** | 契约优先，高度向后兼容 | 抽象优先，面向接口编程 |
| **粒度** | 粗粒度（业务场景驱动） | 细粒度（单一职责驱动） |
| **技术暴露** | 隐藏底层实现 | 暴露技术细节（向量维度、配置对象等） |
| **变更频率** | 极低频，慎重变更 | 高频迭代，可并行演进 |

**核心原则**：对外接口稳定不变，对内接口可灵活重构——这是本架构**隔离变化**的核心能力。

### 3.2 组件接口定义

```python
from abc import ABC, abstractmethod

class VersionResolver(ABC):
    """版本解析器——仅判断去重/新增/重试，不做解析"""
    @abstractmethod
    def resolve(self, ctx: IngestionContext) -> VersionDecision:
        """根据 file_hash + source_kb 查询 MySQL kb_documents"""
        pass

class ParserAdapter(ABC):
    """MinerU 适配器——调用解析服务，写入 MinIO 缓存"""
    @abstractmethod
    def parse(self, ctx: IngestionContext) -> ParsedResult:
        """
        调用 MinerU HTTP API，超时 120s
        约束：elem_id 在文档内全局唯一；chapter_path 必须有值
        """
        pass

class ChunkerEngine(ABC):
    """切块引擎——执行父子块拆分"""
    @abstractmethod
    def chunk(self, parsed: ParsedResult, ctx: IngestionContext) -> ChunkResult:
        """
        输入标准化元素，输出父子块列表
        约束：父块 source_elem_ids = 所有子块并集；切块器不写库
        """
        pass

class TripleWriter(ABC):
    """三库写入器——MySQL → ES → Milvus 顺序写入"""
    @abstractmethod
    def write(self, chunk_result: ChunkResult, ctx: IngestionContext) -> WriteStatus:
        """
        1. 批量插入 MySQL（获取父块ID并回填子块）
        2. 批量写入 ES（仅子块，Bulk API）
        3. 批量写入 Milvus（仅子块，Bulk Insert）
        4. 更新 kb_documents.indexing_status = 1
        约束：父块不写入 ES/Milvus；chunk_uuid 三库严格一致
        """
        pass
```

### 3.3 编排器入口

```python
class IngestionOrchestrator:
    """预处理调度器——唯一对外暴露的内部入口"""
    def __init__(self, resolver: VersionResolver, parser: ParserAdapter,
                 chunker: ChunkerEngine, writer: TripleWriter):
        self.resolver = resolver
        self.parser = parser
        self.chunker = chunker
        self.writer = writer

    def run(self, ctx: IngestionContext) -> Dict[str, Any]:
        """
        状态机：版本判定 → 解析 → 切块 → 三库写入 → 状态更新
        返回：{"action": "skip|new|retry|indexed", "doc_uuid": "...", "chunk_count": ...}
        """
        decision = self.resolver.resolve(ctx)
        if decision.action == "skip":
            return {"action": "skip", "doc_uuid": decision.existing_doc_uuid}

        if decision.action == "retry":
            self._clean_old_chunks(decision.existing_doc_uuid)
            ctx.doc_uuid = decision.existing_doc_uuid

        parsed = self.parser.parse(ctx)
        chunks = self.chunker.chunk(parsed, ctx)
        status = self.writer.write(chunks, ctx)

        return {"action": "indexed", "doc_uuid": ctx.doc_uuid,
                "chunk_count": len(chunks.child_chunks), "write_status": status}
```

## 十二、异常处理与降级策略汇总

| 异常类 | 所属模块 | 触发条件 | 降级/处理策略 |
| :--- | :--- | :--- | :--- |
| `MaxRetryExceededError` | 预处理 | 重试次数 ≥ 3 | 置 `status=failed`，发告警，不继续 |
| `MinerUTimeoutError` | 预处理 | 解析超时（120s） | `retry_count+1`，补偿任务重试 |
| `ChunkingValidationError` | 预处理 | 数据格式异常 | 置 `status=failed`，不重试 |
| `ConfigNotLoadedError` | 路由/排序 | Nacos 不可用 | 使用硬编码默认值，服务继续可用 |
| `MCPTimeoutError` | 路由 | MCP 调用超时 | 忽略 MCP 信号，纯静态匹配，`mcp_enhanced=false` |
| `ClassifierTimeoutError` | 意图理解 | LLM 分类超时 | 立即切换 `IRuleFallback` 规则兜底 |
| `RewriterTimeoutError` | 意图理解 | LLM 改写超时 | 切换规则兜底（去除语气词 + 原样返回） |
| `RerankServiceUnavailableError` | 召回 | Rerank 服务不可用 | 降级为 RRF 融合，`rerank_info.enabled=false` |
| `ESWriteTimeoutError` | 预处理/版本管理 | ES 写入超时 | `retryable=True`，补偿任务仅重写 ES |
| `MilvusConnectionError` | 预处理/版本管理 | Milvus 连接失败 | `retryable=True`，补偿任务仅重写 Milvus |
| `LoggerError` | 全部模块 | 日志写入失败 | 静默失败，仅打印 ERROR 日志，不阻塞主流程 |
| `RunNotFoundError` | 评测 | run_id 不存在 | 返回 404 错误响应 |
| `AnalysisInProgressError` | 反馈闭环 | 分析任务正在进行中 | 返回 409 冲突，提示等待 |
| `DifyAPIError` | 反馈闭环 | Dify API 不可用 | 记录日志，不阻塞主流程，定时任务补偿同步 |
