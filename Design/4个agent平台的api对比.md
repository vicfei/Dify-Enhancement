### 2. 突出特点深度拆解

#### 🔧 Dify：极致的可视化编排与插件生态
*   **特点一：可视化工作流是绝对核心**。它的 API 设计围绕“应用类型”展开（Chatflow/Workflow/Agent），支持节点拖拽、分支、循环、变量聚合。开发者几乎不需要写代码，全靠配置 API 端点来完成复杂的逻辑（如人工介入暂停/恢复）。
*   **特点二：丰富的插件市场（Marketplace）**。Dify 的 API 与插件系统深度绑定，无论是模型供应商、工具（Google Search）还是 MCP 服务器，均可通过界面一键安装并立即通过 API 调用。
*   **特点三：终端用户身份（`user` 字段）隔离**。用同一个应用 API Key 服务成千上万终端用户，依靠 `user` 字段严格隔离会话、文件和记忆，非常适合做 SaaS 应用的后端 API。

#### 🧠 WeKnora：企业级知识治理的“瑞士军刀”（全栈基础设施）
*   **特点一：极细颗粒度的知识管理 API**。除了常规的 CRUD，它提供了 **FAQ 条目的干跑（Dry-run）导入**、**分块级别的启用/禁用**、**知识迁移（跨库搬迁）** 以及 **解析任务取消（`cancel-parse`）**。这些都是生产环境中真实需要的“脏活累活”。
*   **特点二：基础设施可编程（Infrastructure as Code）**。它提供了业界罕见的 **向量存储 CRUD API**（动态创建/删除 Qdrant/Milvus/ES 实例）和 **对象存储后端 CRUD API**（动态注册 MinIO/COS/S3）。这意味着你可以通过 API 动态调整底层资源，实现多租户数据物理隔离。
*   **特点三：原生 MCP 生态 + 工具人工审批**。不仅支持接入 MCP 服务器，还提供了 **`/tool-approvals` 审批接口**。当 Agent 要执行高风险操作（如删除服务器文件）时，会阻塞等待管理员通过 API 点击“批准”，这是企业级安全刚需。
*   **特点四：多组织（空间）共享与权限矩阵**。通过 `/organizations` 和 `/shares` 接口，实现了知识库和 Agent 在不同组织间的共享，并支持 `viewer`/`editor` 权限细分，且 **API Key 可以绑定特定知识库 ID**。

#### 🏢 腾讯乐享：深耕企业 OA 与内容协同
*   **特点一：通讯录与组织架构管理（28个接口）**。这是它的王牌。支持成员/部门的增删改查、入职离职、禁用启用，以及企业微信/HR 系统的平台映射。如果你需要把知识库和公司人员架构绑定，它的 API 是最完备的。
*   **特点二：在线文档的“块（Block）”级编辑**。它提供的不是简单的文件上传，而是 **在线文档块（Block）的创建、嵌套、移动和批量删除**（8个接口）。这使得它更像是一个可编程的在线文档（类似飞书文档/Notion），而不仅是 RAG 数据源。
*   **特点三：经典的三层权限模型（团队/知识库/节点）**。权限控制颗粒度极细，非常适合大型传统企业的文档分级管控。
*   **特点四：纯同步 RESTful 风格**。相比火山引擎和 WeKnora 的大量异步/SSE 流式接口，乐享几乎全是同步请求，接口语义清晰规范（严格区分 GET/POST/PUT/DELETE），对传统后端开发人员非常友好。

#### 📊 火山引擎：AI 智能体的“全透明”数据分析管线
*   **特点一：智能问数（NL2SQL）+ 深度研究（Deep Research）**。它不止做 RAG 问答，而是直接让 AI **写 SQL/Python 代码**进行数据查询。API 返回值包含 `originSql -> rewriteSql -> executeSql` 的完整演进链，以及供前端渲染的 **VChart 图表配置**。
*   **特点二：过程全透明**。对比其他产品的“黑盒”问答，火山引擎的深度研究 API（`/executeTask`）会返回 **中间步骤产物（`running_step`）**，如思考推理、SQL沙箱执行、Python 分析过程。这对于金融、科研等需要审计溯源的场景极其重要。
*   **特点三：三套鉴权体系并存（复杂度最高）**。它不像其他产品统一 API Key，而是区分 **Bearer API_KEY**（知识引擎）、**JWT Token**（智能问数）和 **AK/SK 签名**（TOP 网关生产级调用）。接入成本高，但能适配从轻量测试到企业级高并发的全场景。
*   **特点四：异步任务与 Webhook 回调**。深度研究是长时任务，API 设计采用 `taskId` 轮询，并支持 **`pushNotificationconfig` Webhook 配置**，任务完成后主动回调你的服务器，无需一直轮询。

### 3. 总结：四款产品的本质差异与选型极简指南

| 产品 | **本质** | **极致优势** | **一句话选型** |
| :--- | :--- | :--- | :--- |
| **Dify** | **胶水层** | 把模型、工具、知识库粘合成一个可拖拽的应用 | 想**快速搭建 AI 应用界面**，做 MVP 或内部工具 |
| **WeKnora** | **数据库层** | 把非结构化数据变成可精细治理、可编程调用的知识 | 想**自研 RAG 产品**，需要强大的后台管理 API 和底层存储灵活性 |
| **腾讯乐享** | **OA 层** | 让知识库与公司员工、部门、权限体系无缝融合 | 企业**内部文档协同与管理**是首要需求，AI 只是辅助 |
| **火山引擎** | **大脑层** | 让 AI 直接对结构化数据（库表）做深度逻辑推理与可视化 | 需要 **AI 直接产出数据分析报告、图表和取数结果**，而非简单的文档问答 |

**最强组合建议**：
如果你拥有强大的研发团队，**前端用 Dify 做交互层**，**后端用 WeKnora 做知识存储与检索**，**数据洞察交给火山引擎的 API**，三者通过 API 互联，将成为无敌的 AI 全栈架构。
