# 全局字典与路由模块 —— 接口设计文档

## 一、文档概述

| 项目 | 说明 |
| :--- | :--- |
| **模块名称** | 全局字典与路由模块（Global Router Module） |
| **模块职责** | 根据用户问题，通过关键词匹配与歧义检测，自动路由到最相关的知识库，并输出引导话术与标签 |
| **部署方式** | 独立微服务（Python FastAPI），与 Dify 主服务并行运行 |
| **依赖组件** | Dify API（`/datasets` 接口）、Nacos（配置中心，可选）、MySQL（路由日志） |

## 二、对外暴露的 HTTP 接口

### 2.1 核心路由接口

#### 基本信息

| 项目 | 内容 |
| :--- | :--- |
| **接口名称** | 路由查询 |
| **请求方法** | `POST` |
| **请求路径** | `/api/v1/route` |
| **接口协议** | HTTP/HTTPS + JSON |
| **调用方** | Dify 工作流中的 HTTP 请求节点 |
| **超时建议** | 3000 ms |

#### 请求体（Request Body）

```json
{
  "user_query": "城投债的信用利差最近怎么看？",
  "context_kb": "固收投研"
}
```

| 字段名 | 类型 | 必填 | 描述 |
| :--- | :--- | :--- | :--- |
| `user_query` | string | 是 | 用户输入的原始问题，最大长度 500 字符 |
| `context_kb` | string | 否 | 用户当前所在的知识库（如从前端传递），用于上下文偏置 |

#### 响应体（Response Body）

**场景 A：精准命中（clarity_flag = "clear"）**

```json
{
  "status": "success",
  "routed_kbs": ["固收投研"],
  "confidence": 0.85,
  "clarity_flag": "clear",
  "suggested_question": null,
  "filter_tags": ["城投债", "利差"],
  "matched_keywords": ["城投债", "利差"]
}
```

**场景 B：歧义命中（clarity_flag = "ambiguous"）**

```json
{
  "status": "success",
  "routed_kbs": ["固收投研", "信评知识库"],
  "confidence": 0.62,
  "clarity_flag": "ambiguous",
  "suggested_question": "您的问题涉及多个知识库，请选择：\n1. 固收投研\n2. 信评知识库",
  "filter_tags": ["债券", "信用风险"],
  "matched_keywords": ["债券", "风险"]
}
```

**场景 C：零命中（clarity_flag = "unknown"）**

```json
{
  "status": "success",
  "routed_kbs": [],
  "confidence": 0.0,
  "clarity_flag": "unknown",
  "suggested_question": "抱歉，未找到匹配的知识库。您是否想了解以下内容？\n- 债券/固收类 → 固收投研知识库\n- 股票/权益类 → 股票知识库\n请重新描述您的问题。",
  "filter_tags": [],
  "matched_keywords": []
}
```

| 字段名 | 类型 | 描述 |
| :--- | :--- | :--- |
| `status` | string | 固定返回 `"success"`；路由过程本身不视为失败，无路由结果时返回 `unknown` |
| `routed_kbs` | array[string] | 推荐的知识库列表，按置信度降序排列，最多 3 个 |
| `confidence` | float | 最高分知识库的置信度，范围 0~1，保留 4 位小数 |
| `clarity_flag` | string | `clear` / `ambiguous` / `unknown` |
| `suggested_question` | string | 当 `clarity_flag = ambiguous` 或 `unknown` 时的引导话术，`clear` 时为 `null` |
| `filter_tags` | array[string] | 提取出的业务标签，可用于后续 ES 过滤，最多 10 个 |
| `matched_keywords` | array[string] | 命中的原始关键词列表，最多 10 个（用于日志与审计） |

#### 错误码

| HTTP Status | `code` | 描述 |
| :--- | :--- | :--- |
| 400 | `invalid_param` | 请求参数缺失或格式错误（如 `user_query` 为空） |
| 500 | `internal_error` | 路由引擎内部异常（如词典加载失败） |
| 503 | `config_unavailable` | 词典配置未加载成功，服务暂不可用 |

## 四、与 Dify 平台接口的依赖关系

### 4.1 依赖的 Dify 接口清单

| 序号 | Dify 接口 | 请求方法 | 用途 | 调用频率 | 超时建议 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | `/datasets` | GET | 获取工作空间中所有知识库列表，用于校验 MD 文件中的 `source_kb` 是否仍有效 | 启动时 + 每 1 小时（定时刷新） | 5s |
| 2 | `/datasets/{dataset_id}` | GET | 获取单个知识库的描述信息，用于歧义引导时展示更多上下文 | 歧义触发时（按需） | 3s |

### 4.2 与 Dify 工作流的集成方式

路由模块本身**不与 Dify 前端直接交互**，而是通过 Dify 工作流中的 **HTTP 请求节点** 完成集成：

1. **Dify 工作流发起调用**：在用户输入节点后，插入一个 HTTP 请求节点，指向路由模块的 `/api/v1/route` 接口。

2. **路由模块返回结果**：Dify 工作流解析 `clarity_flag`：
   - `clear`：取 `routed_kbs[0]` 作为 `source_kb` 过滤条件，传入 ES 检索节点。
   - `ambiguous`：将 `suggested_question` 通过 `直接回复` 节点返回给用户，等待用户二次选择。
   - `unknown`：返回 `suggested_question` 引导用户重新描述问题。

3. **二次路由**：当用户二次输入选择（如 “1” 或 “固收投研”）时，工作流再次调用 `/api/v1/route`，此时传入 `context_kb` 参数，路由模块应直接返回对应知识库，不再进行歧义检测。
